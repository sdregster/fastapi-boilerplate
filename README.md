# Упрощенный шаблон FastAPI с Basic Auth

Этот проект представляет собой **упрощенную версию** шаблона для разработки веб-приложений на основе **FastAPI** с базовой аутентификацией через **Basic Auth**. Проект идеально подходит для простых задач, прототипов и случаев, где не требуется сложная система JWT токенов.

## 🎯 Для чего подходит этот шаблон

- **Прототипы и MVP** - быстрое создание работающего приложения
- **Простые проекты** - где не нужна сложная система аутентификации
- **Обучение** - понимание основ FastAPI и аутентификации
- **Внутренние инструменты** - где безопасность не критична
- **Тестирование** - простота отладки и тестирования

## Стек технологий

- **Веб-фреймворк**: FastAPI
- **ORM**: SQLAlchemy с асинхронной поддержкой (asyncpg для PostgreSQL)
- **База данных**: PostgreSQL с поддержкой асинхронных соединений
- **Система миграций**: Alembic с поддержкой асинхронных соединений
- **Авторизация/Аутентификация**: **Basic Auth** (username:password в заголовке Authorization)
- **Хеширование паролей**: passlib с bcrypt
- **Конфигурация**: Pydantic Settings с поддержкой переменных окружения

## 🔐 Система аутентификации Basic Auth

### Как работает Basic Auth

**Basic Auth** - это простой способ аутентификации, где учетные данные передаются в заголовке HTTP запроса:

1. **Формат**: `Authorization: Basic base64(username:password)`
2. **Пример**: `Authorization: Basic YWRtaW46cGFzc3dvcmQ=`
3. **Декодирование**: `admin:password` (base64)

### Преимущества Basic Auth для простых проектов

✅ **Простота реализации** - не требует сложной логики токенов  
✅ **Легкость тестирования** - можно легко тестировать через Postman/curl  
✅ **Быстрая разработка** - не нужно настраивать JWT  
✅ **Понятность** - стандартный HTTP механизм  
✅ **Отладка** - легко увидеть что происходит в заголовках  

### Безопасность

⚠️ **Внимание**: Basic Auth передает пароль в base64 (не зашифрован)  
⚠️ **Рекомендуется**: Использовать только с HTTPS в продакшене  
⚠️ **Ограничения**: Нет автоматического истечения сессии  

### Примеры использования

#### Регистрация пользователя
```bash
curl -X POST "http://localhost:8000/auth/register/" \
  -H "Content-Type: application/json" \
  -d '{
    "email": "user@example.com",
    "phone_number": "+1234567890",
    "first_name": "Иван",
    "last_name": "Иванов",
    "password": "password123",
    "confirm_password": "password123"
  }'
```

#### Вход в систему
```bash
curl -X POST "http://localhost:8000/auth/login/" \
  -H "Content-Type: application/json" \
  -d '{
    "email": "user@example.com",
    "password": "password123"
  }'
```

#### Доступ к защищенному эндпоинту
```bash
curl -X GET "http://localhost:8000/auth/me/" \
  -H "Authorization: Basic dXNlckBleGFtcGxlLmNvbTpwYXNzd29yZDEyMw=="
```

## Основные модули

### **app/auth** - Модуль для аутентификации и авторизации

Модуль отвечает за управление процессами аутентификации (входа пользователей) и авторизации (проверки доступа).

- **`dao.py`**: Объект доступа к данным пользователей
- **`models.py`**: ORM-модели данных для пользователей
- **`router.py`**: Роутеры для маршрутизации запросов аутентификации
- **`schemas.py`**: Pydantic-схемы для валидации данных
- **`utils.py`**: Функции для Basic Auth и хеширования паролей

### **app/dao** - Базовый слой доступа к данным

Модуль содержит абстракции для работы с базой данных.

- **`base.py`**: Базовый класс DAO с общими методами CRUD
- **`database.py`**: Подключение к базе данных и управление сессиями
- **`mixins/`**: Миксины для расширения функциональности моделей

### **app/dependencies** - Управление зависимостями

- **`auth_dep.py`**: Зависимости для Basic Auth аутентификации
- **`dao_dep.py`**: Зависимости для сессий SQLAlchemy

### **app/utils** - Утилиты приложения

Модуль содержит вспомогательные функции и утилиты общего назначения.

- **`case_converter.py`**: Функции для преобразования строк из camelCase в snake_case
- **`logger.py`**: Настройка системы логирования с использованием loguru

### **config.py** - Настройки и конфигурация приложения

Упрощенная система конфигурации на основе Pydantic Settings:

**Основные классы конфигурации**:
- **`RunConfig`**: настройки запуска (хост, порт)
- **`DatabaseConfig`**: конфигурация БД (URL, пулы соединений)
- **`LoggingConfig`**: настройки логирования (уровень, формат, папка logs)

**Примеры переменных окружения**:
- `APP_CONFIG__DB__URL`: URL подключения к базе данных
- `APP_CONFIG__RUN__HOST`: хост для запуска приложения
- `APP_CONFIG__RUN__PORT`: порт для запуска приложения
- `APP_CONFIG__LOGGING__LEVEL`: уровень логирования (DEBUG, INFO, WARNING, ERROR)
- `APP_CONFIG__LOGGING__DIRECTORY`: папка для хранения логов
- `APP_CONFIG__LOGGING__MAX_SIZE`: максимальный размер файла лога в MB
- `APP_CONFIG__LOGGING__BACKUP_COUNT`: количество файлов бэкапа

## Запуск приложения

1. Клонируйте репозиторий:

   ```bash
   git clone https://github.com/Yakvenalex/FastApiWithAuthSample.git .
   ```

2. Установите зависимости:

   ```bash
   pip install -r requirements.txt
   ```

3. Создайте и настройте `.env` файл:

   ```env
   # База данных PostgreSQL
   APP_CONFIG__DB__URL=postgresql+asyncpg://postgres:password@localhost:5432/fastapi_auth
   APP_CONFIG__DB__ECHO=false
   
   # Настройки запуска (опционально)
   APP_CONFIG__RUN__HOST=0.0.0.0
   APP_CONFIG__RUN__PORT=8000
   
   # Настройки логирования (опционально)
   APP_CONFIG__LOGGING__LEVEL=INFO
   APP_CONFIG__LOGGING__DIRECTORY=logs
   APP_CONFIG__LOGGING__MAX_SIZE=10
   APP_CONFIG__LOGGING__BACKUP_COUNT=5
   ```

4. Запустите приложение с Uvicorn:

   ```bash
   uvicorn app.main:app --reload --port 8000
   ```

## Миграции базы данных

1. Инициализируйте Alembic:

   ```bash
   cd app
   alembic init -t async migration
   ```

   Затем переместите `alembic.ini` в корень проекта.

2. В `alembic.ini` установите `script_location` как `app/migration`.

3. Создайте миграцию:

   ```bash
   alembic revision --autogenerate -m "Initial migration"
   ```

4. Примените миграции:

   ```bash
   alembic upgrade head
   ```

## 📝 Система логирования

Проект включает настраиваемую систему логирования с использованием **loguru**:

### **Особенности логирования**

✅ **Множественные выходы**: консоль + файлы  
✅ **Ротация логов**: автоматическое создание новых файлов при достижении размера  
✅ **Сжатие**: старые логи автоматически сжимаются в ZIP  
✅ **Разделение по уровням**: отдельные файлы для разных уровней логирования  
✅ **Цветной вывод**: красивый формат с эмодзи и цветами  
✅ **Настраиваемость**: все параметры через переменные окружения  

### **Файлы логов**

- **`logs/app.log`** - основной файл логов (уровень INFO)
- **`logs/error.log`** - только ошибки (уровень ERROR)  
- **`logs/debug.log`** - отладочная информация (уровень DEBUG)

### **Настройка логирования**

```bash
# Уровень логирования
APP_CONFIG__LOGGING__LEVEL=DEBUG

# Папка для логов
APP_CONFIG__LOGGING__DIRECTORY=logs

# Максимальный размер файла (MB)
APP_CONFIG__LOGGING__MAX_SIZE=10

# Количество файлов бэкапа
APP_CONFIG__LOGGING__BACKUP_COUNT=5

# Включение/выключение вывода
APP_CONFIG__LOGGING__CONSOLE_OUTPUT=true
APP_CONFIG__LOGGING__FILE_OUTPUT=true
```

### **Использование в коде**

```python
from app.utils import get_logger

logger = get_logger(__name__)

logger.debug("Отладочная информация")
logger.info("Информационное сообщение")
logger.warning("Предупреждение")
logger.error("Ошибка")
logger.critical("Критическая ошибка")
```

## 🔄 Миграция с JWT на Basic Auth

Если у вас есть существующий проект с JWT, основные изменения:

1. **Убрать JWT зависимости**: `python-jose`, `bcrypt`
2. **Заменить аутентификацию**: JWT токены → Basic Auth заголовки
3. **Упростить конфигурацию**: убрать JWT настройки
4. **Обновить тесты**: адаптировать под Basic Auth
